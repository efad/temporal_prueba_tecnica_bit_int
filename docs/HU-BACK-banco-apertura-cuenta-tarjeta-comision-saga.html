ENABLER [BACK] Apertura de cuenta con creación de tarjeta y cobro de comisión mediante Saga Orquestada

Descripción

Implementar un flujo distribuido para crear cuenta, emitir tarjeta y cobrar comisión de emisión con patrón Saga en 3 microservicios REST sin autorización, usando únicamente Orquestación y Circuit Breaker para resiliencia ante latencia alta.

Contexto

El alta de cuenta con tarjeta y cobro de comisión requiere consistencia entre servicios para evitar cuentas o tarjetas huérfanas. Se necesita un orquestador que controle el flujo y active compensaciones cuando falle un paso. El patrón seleccionado es Saga con Orquestación obligatoria; no se permite Coreografía Event-Driven. Además, se requiere Circuit Breaker optimizado para prevenir fallos en cascada por dependencias lentas. La entrega debe incluir evidencia ejecutable por equipo técnico.

Diseño Técnico

Microservicios (3)

  • account-opening-orchestrator-service: expone endpoint de apertura y orquesta la Saga.
  • account-service: crea y revierte cuenta bancaria.
  • card-service: crea y revierte tarjeta, y aplica cobro de comisión de emisión contra la cuenta creada.

Flujo Saga Orquestada

  1. Orquestador crea cuenta en account-service.
  2. Si cuenta creada, solicita creación de tarjeta en card-service.
  3. Si tarjeta creada, card-service ejecuta cobro de comisión de emisión.
  4. Si todo OK, Saga finaliza en COMPLETED.
  5. Si falla tarjeta o comisión, se compensa: reverso de tarjeta (si aplica) y reverso de cuenta.

Resiliencia (Circuit Breaker)

  • Circuit Breaker por cada dependencia remota en el orquestador con timeout, umbral de slow calls y transición controlada OPEN/HALF_OPEN/CLOSED.
  • Cuando el circuito esté OPEN, el flujo no continúa y se registra estado PENDING_RETRY o FAILED según regla definida.
  • Observabilidad mínima por sagaId: latencia, estado de circuito, compensaciones y resultado final.

Criterios de Aceptación

  1. CA-01 Se implementan 3 microservicios sin autorización y el orquestador consume exactamente a account-service y card-service para completar apertura de cuenta con tarjeta y comisión.
  2. CA-02 La implementación usa únicamente Saga por Orquestación; no se permite Coreografía (Event-Driven) ni dependencia de bus de eventos para coordinar la transacción.
  3. CA-03 Si falla la creación de tarjeta o el cobro de comisión, se ejecutan compensaciones automáticas y trazables para dejar el sistema sin artefactos inconsistentes.
  4. CA-04 El Circuit Breaker del orquestador se activa por error y por latencia alta sostenida, bloquea llamadas en cascada y permite recuperación progresiva en HALF_OPEN.
  5. CA-05 Se entrega repositorio Git con el código fuente de los 3 microservicios, README de ejecución local y pruebas automáticas (unitarias + integración mínima de Saga) con evidencia de ejecución.
  6. CA-06 Se entrega cliente de consumo (colección Postman o cliente HTTP) con evidencia de al menos 3 escenarios: éxito completo (cuenta+tarjeta+comisión), fallo en creación de tarjeta con compensación y fallo por latencia con Circuit Breaker abierto.
  7. CA-07 Se entregan diagramas C4 nivel 2 (Container) del flujo de orquestación y dependencias entre microservicios, junto con documento de configuración técnica con parámetros de despliegue y resiliencia.

Entregables Técnicos

  • Repositorio Git con código fuente versionado de account-opening-orchestrator-service, account-service y card-service.
  • Pruebas unitarias y de integración mínima del flujo Saga con evidencia de ejecución.
  • Cliente de consumo (colección Postman o cliente HTTP) para probar endpoints de los 3 microservicios.
  • Evidencia de ejecución de al menos 3 escenarios: éxito end-to-end (cuenta + tarjeta + comisión), fallo en creación de tarjeta con compensación y Circuit Breaker abierto por latencia.
  • Diagramas C4 nivel 2 (Container) con relación entre orquestador, servicios de cuenta y tarjeta, y puntos de compensación.
  • Documento de configuración técnica (timeouts, umbrales de Circuit Breaker, reintentos, variables de entorno y puertos por servicio).
